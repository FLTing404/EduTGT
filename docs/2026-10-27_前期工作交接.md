### 2.2 图的定义

- **模块 module**：AAA、BBB、CCC、DDD、EEE、FFF、GGG，对应 `code_module`。
- **开课实例 presentation**：如 `2013J`、`2014B`，同一模块可以有多个实例。
- **学生节点**：同一模块内按学生 ID 合并，可能连接该生不同实例的访问。
- **站点节点**：以模块、presentation、`id_site` 组合标识；不是知识点节点。
- **正边**：某学生在某相对日访问某站点的聚合记录，观测标签均为 1。`sum_click` 表示该记录的访问强度，不等于当前主模型直接使用的边权。
- **负边**：运行时替换正边终点站点，保留学生和时刻；并非原数据标注的“确定不会访问”。

清洗时按 `(id_student, code_module, code_presentation, id_site, date)` 合并，并求 `total_clicks=sum(sum_click)`；没有 VLE 站点映射或点击数非正的记录会被丢弃。磁盘节点编号从 1 开始，学生在前、站点在后；`Dataset` 读取后重新压缩到从 0 开始，连接标签或特征时应使用一致的映射，不能混用两套编号。

主实验不属于学生成绩分类。它回答的是：给定学生、候选资源和时刻，模型能否区分已观测交互与采样负例。其高 AUC 不可直接解释为课程通过预测准确率或资源推荐的线上效果。

### 2.3 时间编码与时间切分

多实例合并使用合成时间戳：

```text
ts = presentation 在模块内的排序索引 × 1000 + 相对开课日 date
```

这将各实例排成时间块，不是自然日历上的真实时间差。开课前访问的 `date` 可以为负；由 `ts // 1000` 反解实例时会发生边界错误，详见第 9 节。

[utils.Dataset](../EduTGT/utils.py) 在训练时根据全部边时间戳重新计算 10% 和 20% 分位数：

```text
train：ts <= q10
val：q10 < ts <= q20
test：ts > q20
new nodes：全图节点集合 - train 中出现的节点集合
nn_val / nn_test：对应时间集合内，任一端属于 new nodes 的边
```

因此切分约为 **10% / 10% / 80%**，不是常见的 70% / 15% / 15%。同日记录有相同时间戳，实际行数不会严格按比例。`nn_test` 是 `test` 的子集，不能与 test 当作互斥样本相加。

## 3. 方法实现与名称对应

### 3.1 继承自 ContraTGT 的部分

主框架是“对比预训练 → 监督链路微调”：

1. 为源学生、正目标和负目标构建空间邻域序列与时间事件序列。空间分支采近期邻居；时间分支先定位节点前一次交互，再取此前的全局事件窗口，交替放入事件两端节点，并非单纯取该学生自己的最近交互。
2. 分别经空间、时间两个 Transformer 编码器编码。
3. 每路组合首位置表示和其余位置的均值，再融合得到节点嵌入。
4. 将学生与候选站点表示组合，使用预测头输出链路存在概率。
5. 预训练包含可学习增强、Top-k 相关模块及一致性、多样性、对比学习项；微调采用正负样本 BCE。

`getEmbed` 的实际输出维度为补齐后的特征维 `d`：四个读出向量拼接后经 `Linear(4d,d)` 融合；链路头先将端点拼接经 `Linear(2d,d)`，再用 `d→64→10→1` 的 MLP。注意力使用 mask，最终非首位置池化仍是普通均值，并非按有效位置重新加权。

预训练每批先更新 Top-k 增强器 6 次，再更新主模型 3 次；增强器目标是一致性项加 `0.6 × 多样性项`，主模型采用原/增强视图正余弦项与负例余弦项，而非直接用真实边标签 BCE。预训练按平均训练对比损失早停，耐心为 5，结束后加载最佳 checkpoint。

源码：[model.py](../EduTGT/model.py)、[graph_transformer.py](../EduTGT/graph_transformer.py)、[sampling.py](../EduTGT/sampling.py)、[pretrain.py](../EduTGT/pretrain.py)。当前 `model.py` 和 `graph_transformer.py` 与 `ContraTGT/` 中对应文件相同，`sampling.py` 的差异主要为注释；不应把继承的双分支架构重新计为本项目新提出的网络结构。

### 3.2 教育场景扩展：PANS

实现入口为 [main_ablation_pres_relation.py](../EduTGT/methods/main_ablation_pres_relation.py)，负采样实现为 [course_pres.py](../EduTGT/course_pres.py)。这里的 `ablation_pres` 在当前结果中代表 **EduTGT 主方法**。

先按每个 presentation 的原始 `id_site` 集合计算 Jaccard 相似度矩阵 `W`，对角线为 1。给定当前正边所属实例 `p`，对训练集中出现过的候选终点 `j`，按其所属实例 `q(j)` 给权重：

```text
biased(j | p) ∝ max(W[p, q(j)], 1e-8)
P(j | p) = λ × Uniform(训练 dst) + (1-λ) × biased(j | p)
λ = pres_mix_uniform，默认 0.35
```

`λ=1` 时为均匀采样，`λ` 越小越偏向关系权重。该参数不是 STC 损失权重。当前实现通过改变训练负例分布引入实例信息，没有新增独立的 CPE 编码层。

预训练会在数据目录存在 `pres_relation.json` 时自动加载 PANS。`methods/main.py` 的微调仍使用均匀采样，但其共享预训练权重可能已经受该文件影响；正式比较前必须记录预训练是否使用关系文件。

## 4. 对比方法与评测协议

### 4.1 三个时序图基线

| 表中名称 | 实现入口 | 本地实现范围 |
|---|---|---|
| TGN | [tgn/runner.py](../EduTGT/baseline/tgn/runner.py)、[tgn/model.py](../EduTGT/baseline/tgn/model.py) | PyG `TGNMemory` + 自定义消息 MLP 和链路预测头，未堆叠图邻域编码器；需要 `torch-geometric` |

| JODIE | [tncn/runner.py](../EduTGT/baseline/tncn/runner.py)、[tncn/model.py](../EduTGT/baseline/tncn/model.py) | JODIE 风格简化实现，目录名沿用 `tncn`；训练优化静态 embedding 和链路头，GRU 演化在 `no_grad` 下进行、未从该目标获得梯度；不能标为 TNCN 实验 |

### 4.2 指标与可比性边界

每条正边配一条采样负边，形成约 1:1 的评测标签。输出指标主要为 ROC-AUC、AP 和 ACC；ACC 依赖 0.5 阈值，AP 是 `average_precision_score`，不是所有文献中通用的梯形积分 PR-AUC。

| 项目 | 主模型及其扩展 | TGN / TGAT / JODIE |
|---|---|---|
| 数据入口 | 相同 `ml_*.csv`、`.content`、时间分位划分 | 复用 `Dataset` 和数据适配器 |
| 训练负例候选 | 训练边出现过的 dst | 训练边出现过的 dst |
| 验证/测试负例候选 | 全图 dst | 训练 dst |
| AUC / AP 汇总 | 每个 batch 单独计算，再简单平均 | 合并整个 split 的预测后计算 |
| 默认 batch size | 800 | 一键批跑统一 200；JODIE 单 runner 默认 400 |
| weight decay | 1e-5 | Adam 默认未设置同值 |
| 随机状态 | random / NumPy 设置不完整覆盖 torch | 有独立 seed 工具 |

因此，“共用同一时间切分”成立，“所有评测细节完全一致”不成立。后续正式对比应固定评测边和负例、统一全局指标，保留 `test` 与 `nn_test` 两组结果。

当前随机负例没有形成固定的、经已知正边过滤的候选集；采到正目标或其他实际正交互的可能性也需处理。若改成资源推荐任务，还应另行定义每个学生的候选站点和排序指标。

## 7. 下游课程通过预测

### 7.1 任务、标签和切分

下游代码位于 [downstream_pass_prediction/](../downstream_pass_prediction/)，现有数据为 AAA、BBB、CCC。

每个“学生—模块—presentation”是一条注册标签：`Pass`、`Distinction` 为 1，`Fail`、`Withdrawn` 为 0。标签来自 `studentInfo.final_result`，保留字段为 `id_student, ml_node_id, code_module, code_presentation, is_pass`。只保留能映射到图节点的学生，某次注册若无可用锚点会在编码阶段跳过。

按学生进行约 70% / 15% / 15% 分层切分，分层标签取该学生任一注册是否通过（`max`）；同一学生的各实例落入同一 split。已检查当前文件中没有学生交叠。**这不是主链路任务的时间切分。**

当前 `load_graph_bundle()` 仍载入完整图的邻接和事件列表，学生 split 只划分监督标签，不会删除测试学生的无标签行为。因此现有设定属于共享图上的学生标签切分，“学生标签集合无交叠”不等于“编码器及行为上下文严格未见测试学生”；严格归纳验证需要另建训练可见图。

### 7.2 E1 / E2 与训练协议

- **E1（scratch）**：随机初始化 SpatialTemporal，再训练通过预测头。
- **E2（pretrain）**：加载 `outputs/pretrain/<data_name>.pth`，先冻结编码器，再以差分学习率解冻微调。
- 两者当前代码均固定空间/时间长度为 **30/21**。`方案.md` 和部分 YAML 注释所述 E1 用 40/31 已过时。
- 每次注册选该生在该 presentation、观测截止日内最后一条边作为锚点，取源学生的 `getEmbed`，接 `Linear(d,1)` 二分类头。
- 使用 `BCEWithLogitsLoss`，`pos_weight=train_neg/train_pos`；Adam，weight decay=1e-5，batch=32，最多 50 epoch，以验证 AUPRC 选择最佳模型，最终测试一次，ACC/F1 默认阈值 .5。
- E1 常用 lr=1e-4、耐心 10。E2 单跑 YAML 默认 lr=5e-5、冻结 10 epoch、头部 lr×5、编码器 lr×.5、耐心 15；批跑和后续补跑另有 .6、.65 的编码器倍率，必须按 CSV 区分。

84 条现有 `runs_st.jsonl` 记录的 `t_star_relative_day` 均为空，属于完整观测窗口。代码虽支持截止日设定，已有结果尚未形成按第 30/60/90 天等预测的早期预警实验。

## 9. 已确认的问题、影响与建议

### 9.1 PANS 候选池退化：当前最关键的方法有效性问题

核查方法：按每模块实际 `ml` 的 `ts<=q10` 取训练边，再用 `node_map.csv` 识别训练 dst 所属 presentation。结果如下：

| 模块 | 训练正边 | 不同训练 dst | 所有训练 dst 所属实例 |
|---|---:|---:|---|
| AAA | 29,399 | 123 | 2013J |
| BBB | 114,247 | 283 | 2013B |
| CCC | 89,337 | 89 | 2014B |
| DDD | 187,006 | 353 | 2013B |
| EEE | 77,716 | 55 | 2013J |
| FFF | 326,108 | 256 | 2013B |
| GGG | 28,388 | 80 | 2013J |

候选全部属于实例索引 0，因此对任何正边实例 `p`，每个候选权重都是相同的 `max(W[p,0],1e-8)`，归一化后严格等于 `1/候选数`。与均匀分布混合后仍为均匀分布，λ 的数值不改变分布。六份现存关系文件的 `W` 均为单位阵；FFF 当前关系文件缺失，但其训练候选只有一个实例的事实同样成立。

这是**对当前数据和实现已验证的结论**。`np.random.choice(p=均匀权重)` 与 `np.random.randint` 仍可能消耗不同随机数并生成不同具体负例，叠加 torch 随机状态未控制，足以导致同分布下训练分数不同；不能把这种差异解释成课程结构带来的采样增益。

后续应先明确想研究的任务：若想在多实例候选中应用实例关系，训练时间窗和可用候选需要真实覆盖多个实例，同时避免引入未来不可用资源；若坚持当前训练候选，则需重新设计在该候选池内部有区分度的先验。不能为获得非均匀结果而直接把未来站点加入训练。

### 9.2 两种变体存在已验证的实现错误

| 问题 | 代码证据 | 已验证行为及影响 |
|---|---|---|
| no_temporal 只设 `tmp_sample=1` | [model.py](../EduTGT/model.py) 的 `getEmbed` 对 `temporal_output[:,1:,:]` 求均值 | 长度 1 时切片为空，最小运行输出全部 NaN；没有实现有效的空间单分支消融 |
| course_progress 写回整数 | [main_ablation_course_progress.py](../EduTGT/methods/main_ablation_course_progress.py) 第 47—49 行 | `Dataset` 的时间为 `torch.long`；归一化浮点写回后如 `[10,20,30]→[0,0,1]`；时间顺序信息大量丢失，`ts//1000` 也全变首实例 |

no_temporal 的独立验证仅构建 `SpatialTemporal(4,128,N=2)`，输入时间序列长度 1，检查 `torch.isnan(getEmbed(...)).all()`，得到 `True`；未运行完整训练。修复后必须重新生成受影响实验，不能只更改表格标题。

### 9.3 合成时间戳的负日期解码错误

`ts=实例索引×1000+date`，当 `date<0` 时，整数除法将时间归入前一个块。例如第二实例的 `date=-5` 得到 `ts=995`，`995//1000=0`，会被当作第一实例；`995%1000=995` 也不是原始相对日。

下游 [st_graph.py](../downstream_pass_prediction/src/st_graph.py) 按 `//1000` 过滤实例、按 `%1000` 截断日期，已核查到：

| 模块 | 站点所属实例与时间块不符的边 | 无截断最终锚点取自错误实例的数量 |
|---|---:|---:|
| AAA | 22,038 | 31 |
| BBB | 64,951 | 59 |
| CCC | 59,151 | 131 |

PANS 的 `ts//1000` 同样存在边界问题。修复建议是显式保存每条边的 presentation 和原始相对日，构图时间与业务属性分别处理；若继续使用时间块，也必须采用能唯一反解负日期的约定，并同步修改所有消费者。

|---|---|---|
| `date_unregistration` 在静态特征中 | 对 Withdrawn/通过标签和早期预警可能包含期末信息 | 按预测时刻屏蔽未来事件属性，另做无退课时间特征对照 |
| 全图拟合类别字典、缺失填补和标准化 | 严格归纳评测中使用了未来分布信息 | 训练范围拟合、验证/测试只转换，保存拟合对象 |
| 主模型与基线负例池不同 | 负例难度不同，指标不能直接视为公平对比 | 固定候选可用性与同一组评测负例 |
| batch均值与全局指标不同 | AUC/AP 不可等同，batch大小变化会影响值 | 合并预测后统一计算，保留逐样本分数 |
| 无已知正例过滤 | “负例”可能是实际正交互 | 明确协议，过滤范围和时间可用性均需记录 |
| 主微调 split 最后一条边遗漏 | `min(num_instance-1,...)` 配合右开切片遗漏末边，极小尾批可能为空 | 切片终点改为样本数并验证覆盖；重新生成正式指标 |

数据概览 notebook 的点击探索只使用前 200 万行，并非随机抽样或全量统计；其探索性图表不能直接代表全量 OULAD 行为分布。

### 9.5 随机性、完整权重与保存逻辑

1. `utils.init_seeds` 只设 Python、NumPy；主模型微调没有同时设置 torch，预训练未调用该函数。因此仅记录 `--seed` 不足以复现。
2. 两个 `TimeEncode` 在 SpatialTemporal 外部创建，不在主 optimizer 和保存的 `state_dict` 中；concat 模式的 `fc1` 随机线性参数没有随主体保存。只加载主模型权重不能还原完整输入变换。
3. `--tolerance` 虽被解析，但没有传给 EarlyStopping，实际使用类默认值。
4. 主微调入口仅在触发早停时加载最佳 checkpoint 并写最终模型；若跑满 epoch，测试使用最后轮，可能没有写出新的最终模型文件。应统一为训练结束始终恢复并保存最佳验证模型。
5. 结果日志缺 seed、数据/预训练哈希、代码版本、运行命令；同名文件被覆盖后难以追溯。
6. 批跑从共享 JSONL 读取本次新增的最后一行，未来并发执行有误配风险；本次核查未发现已成功记录串写，应通过独立 run_id 和独立输出目录预防。
7. 基线的最佳权重快照也存在被后续训练改变的风险：TGN 内存保存 `state_dict()` 未 clone；TGAT/JODIE 使用 `v.cpu()`，在 CPU 运行时仍可能共享存储。最小 PyTorch 验证显示共享状态会随参数更新改变；历史各次运行受影响的程度仍待追溯，建议保存时显式 clone / deepcopy 并核对恢复后的参数。
