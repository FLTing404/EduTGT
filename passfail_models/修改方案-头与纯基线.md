## 二、main_passfail 中的课程级聚合方式（与之一致）

`main_passfail.py` 的课程级评估分两步，新加的 Logistic/LSTM 等也应采用同一套聚合与评估方式。

### 2.1 边级分数收集

- 对当前集合（train/val/test）的**每条边**前向得到模型输出 `pos_prob`（标量，通过概率），并记录该边的 `(u, i, ts, score, label)`。
- 实现见 `collect_edge_scores(data, batch_size, model, ...)`：遍历 data 的边，每边得到 `(u_np[j], i_np[j], ts_np[j], pos_prob_np[j], label_01[j])`，放入 `edge_list`。

### 2.2 按 (u,i) 时间加权聚合（课程级 score 与 label）

- 函数：`aggregate_course_level_time_weighted(edge_list)`（方案 E：按 (u,i) 时间加权平均 pos_prob）。
- 逻辑：
  1. **按 (u,i) 分组**：把 `edge_list` 里所有 `(u, i, ts, score, label)` 按 `(u,i)` 分组，同一 (u,i) 的多条边放在一起。
  2. **课程级分数**：对每个 (u,i)，设其边集合为 `[(ts_1, s_1, l_1), (ts_2, s_2, l_2), ...]`。  
     - 时间加权平均：`s_ui = sum(ts * s for ts, s, _ in arr) / w_sum`，其中 `w_sum = sum(ts for ts, _, _ in arr)`（以时间 ts 为权重）。  
     - 若 `w_sum == 0`，则退化为简单平均：`s_ui = sum(s for _, s, _ in arr) / len(arr)`。
  3. **课程级标签**：同一 (u,i) 下所有边的 label 相同，取任一边即可，例如 `labels.append(arr[0][2])`。
- 返回：`scores`（每个 (u,i) 一个标量）、`labels`（每个 (u,i) 一个 0/1），均为 numpy 数组，按 `sorted(groups.keys())` 的 (u,i) 顺序一致。

### 2.3 课程级指标计算

- 在聚合得到的 `scores` 与 `labels` 上计算：
  - **AUC**：`roc_auc_score(labels, scores)`
  - **AP**：`average_precision_score(labels, scores)`
  - **Acc**：`(labels == (scores >= 0.5).astype(int)).mean()`
  - **Loss**（可选）：`log_loss(labels, np.clip(scores, 1e-7, 1-1e-7))`
- 见 `eval_course_level`：先 `collect_edge_scores` → `aggregate_course_level_time_weighted` → 再算上述指标。

**约定**：新增的 ContraTGT+Logistic、ContraTGT+LSTM 等若在边级得到分数（例如每条边一个概率），应按上述**时间加权平均**聚合成课程级 score，再算 AUC/AP/Acc；若直接在 (u,i) 级得到一个分数（如 Logistic/LSTM 对每个 (u,i) 只输出一个值），则无需边级聚合，但评估仍是在 (u,i) 级算 AUC/AP/Acc，与 main_passfail 口径一致。

## 三、共享基础设施

### 3.1 数据与划分

- 复用 `script/utils.py`：`get_data_paths(args)`、`Dataset(..., train_ratio=0.1, val_ratio=0.1, test_ratio=0.8, random_state=seed)`。
- 得到 `train_data` / `val_data` / `test_data`（边级）；再从中得到 **(u,i) 级** 的 train/val/test 集合与标签（每个 (u,i) 一个 label，取该 (u,i) 任一边的 label 即可，因同 (u,i) 同 label）。

### 3.2 原始特征（供「纯」方法用）

- **单向量 per (u,i)**（给 纯 Logistic / 纯 MLP）：  
  对每个 (u,i)，用其**所有边**对应的节点特征与时间等构造一个固定维向量，例如：  
  `[feat_u, feat_i, mean_ts, max_ts, count_edges, ...]`  
  即：学生节点特征 + 课程节点特征 + 该 (u,i) 的简单统计（均值/最大时间、边数等）。特征从 `oulad.content` + `ml_oulad.csv` 读取，与现有数据格式一致。

- **序列 per (u,i)**（给 纯 LSTM）：  
  对每个 (u,i)，按时间排序其边，每条边对应一帧特征：  
  `[feat_u, feat_i, ts, ...]`（或再拼该时刻的统计），得到 `(seq_len, feat_dim)`。  
  不同 (u,i) 的 `seq_len` 不同，需做 **padding + mask** 或统一截断到固定长度。

### 3.3 预训练表示（供 ContraTGT+头 用）

- **单向量 per (u,i)**（给 ContraTGT + Logistic）：  
  - 用预训练好的 `SpatialTemporal`，对 **每条边** 前向得到 pair 表示（例如 `getEmbed` 得到 src_embed、tgt_embed，拼成 256 维，或取 `linkPredict` 前一层 的 `pos_embed`）。  
  - 再按 (u,i) **聚合**：同一 (u,i) 的多条边取 **时间加权平均**（与 `aggregate_course_level_time_weighted` 一致）或取**最后一条边**的表示，得到每个 (u,i) 一个向量。  
  - 只使用 **当前划分** 的边（train/val/test 各自只用自己的边），避免泄露。

- **序列 per (u,i)**（给 ContraTGT + LSTM）：  
  - 同上对每条边得到 256 维（或 128 维）向量。  
  - 按 (u,i) 分组、按时间排序，得到每个 (u,i) 的序列 `(T_ui, dim)`，再 padding/截断到统一长度。

建议在 `passfail_models` 下新增 **`passfail_data.py`**（或 `utils_passfail.py`）统一实现：

- `get_ui_splits_and_labels(edges_file, train_ratio, val_ratio, test_ratio, seed)`  
  → 返回：`train_ui, val_ui, test_ui`（(u,i) 集合或索引）、`y_train, y_val, y_test`（课程通过/不通过标签）。
- `build_raw_features_ui(edges_file, feature_file, train_ui, val_ui, test_ui, ...)`  
  → 返回：`X_train, X_val, X_test`（单向量）及（若需要）`X_train_seq, X_val_seq, X_test_seq`（序列）+ 各 mask/length。
- `extract_contratgt_embeddings(edges_file, feature_file, pretrain_path, train_data, val_data, test_data, ...)`  
  → 调用 script 下 model/sampling，按边前向、再按 (u,i) 聚合成单向量与序列，返回与上面同一 (u,i) 划分对齐的 `X_train, X_val, X_test` 及序列版。

这样「纯」与「ContraTGT+」共用同一 (u,i) 划分和同一套评估接口。

## 四、各脚本职责与接口

### 4.1 预训练表示提取（建议单独模块，便于复用）

- **文件**：`passfail_models/extract_embeddings.py`（或合并在 `passfail_data.py` 中）。
- **输入**：`--data_dir`、`--seed`（与下游一致）、预训练权重路径（可由 `get_data_paths` + 固定子路径得到）。
- **输出**：  
  - 单向量：(u,i) 级 `X_train, X_val, X_test`（numpy 或保存为 npz），与 `get_ui_splits_and_labels` 的 (u,i) 顺序一致。  
  - 序列：(u,i) 级 `X_train_seq, X_val_seq, X_test_seq`（padding 后）+ `mask` 或 `length`，供 LSTM 使用。  
- **实现要点**：复用 `main_passfail` 里的数据加载、`get_adj_list`、`init_offset`、`get_neighbor_list`、`get_unique_node_sequence` 等；加载预训练 `SpatialTemporal`，**只前向、不反传**；对每条边得到 pair embedding，再按 (u,i) 聚合（时间加权或最后边），并区分 train/val/test 边以严格按划分产出。

### 4.2 Logistic：预训练 + Logistic 与 纯 Logistic

- **文件**：`passfail_models/train_logistic.py`。
- **参数**：  
  - `--data_dir`、`--seed`（默认与 run_paper_eval 一致）；  
  - `--mode`：`pure` | `contratgt`；  
  - 可选：`--output_dir`、`--C`（正则化）等。
- **逻辑**：  
  - `pure`：用 `build_raw_features_ui` 得到 (u,i) 级 `X_train, X_val, X_test` 和 `y_*`；训练 `sklearn.linear_model.LogisticRegression`；在 val 上可选调参，在 test 上算课程级 AUC/AP/Acc。  
  - `contratgt`：用 `extract_contratgt_embeddings` 得到的单向量 `X_*` 与同一 `y_*`；同样训练 LogisticRegression，评估方式相同。
- **输出**：与 `main_passfail` 对齐的 CSV 列（如 `Train_AUC, Val_AUC, Test_AUC, Test_AP, Test_Acc` 等），写入 `result/passfail/<data_dir>/logistic_pure_*.csv`、`logistic_contratgt_*.csv`（或带 seed 后缀）。

### 4.3 LSTM：预训练 + LSTM 与 纯 LSTM

- **文件**：`passfail_models/train_lstm.py`。
- **参数**：`--data_dir`、`--seed`、`--mode`（`pure` | `contratgt`）、`--hidden_size`、`--num_layers`、`--max_len`（序列截断/ padding 长度）、`--output_dir` 等。
- **逻辑**：  
  - **输入**：  
    - `pure`：`build_raw_features_ui` 的序列版 `X_*_seq` + mask；  
    - `contratgt`：`extract_contratgt_embeddings` 的序列版。  
  - **模型**：LSTM(embed_dim, hidden_size, num_layers) → 取最后有效步或 last hidden → 全连接 → sigmoid；训练用 BCE，课程级评估时对 (u,i) 一个预测值算 AUC/AP/Acc。  
  - 序列长度不一致时用 padding + `pack_padded_sequence` 或 mask 掉 padding，保证课程级一个 (u,i) 一个预测。
- **输出**：同上，CSV 写入 `result/passfail/<data_dir>/lstm_pure_*.csv`、`lstm_contratgt_*.csv`。

### 4.4 纯 MLP

- **文件**：`passfail_models/train_mlp.py`。
- **参数**：`--data_dir`、`--seed`、`--mode`（`pure`；若以后加 `contratgt` 也可复用同一脚本）。
- **逻辑**：与 Logistic 相同的数据接口；`pure` 时用原始特征 (u,i) 单向量 → 2～3 层 MLP → sigmoid，BCE 训练，课程级评估。
- **目的**：与 `main_passfail`（ContraTGT + MLP 头）形成对照：「纯 MLP」vs「预训练 + MLP 头」。

## 五、评估与结果格式统一

- 所有脚本在 **课程级 (u,i)** 上计算：AUC、AP、Acc、（可选）Loss。
- 输出 CSV 列与 `main_passfail` 对齐，例如：  
  `Train_AUC, Train_AP, Train_Acc, Val_AUC, Val_AP, Val_Acc, Test_AUC, Test_AP, Test_Acc`；若沿用 NN_Test 可再加 `NN_Test_*`。
- 文件命名建议：  
  `{method}_{pure|contratgt}_{data_name}.csv` 或带 `_s{seed}.csv`，便于 `run_paper_eval.py` 汇总。

## 六、与 run_paper_eval 的衔接

- 若希望「一键跑齐」所有对比：  
  可在 `passfail_models/run_paper_eval.py` 中增加参数，例如 `--methods contratgt,logistic_pure,logistic_contratgt,lstm_pure,lstm_contratgt,mlp_pure`，对每种方法用同一批 seed 依次调用对应脚本，并把生成的 CSV 拷贝为 `*_s{seed}.csv`，最后汇总 mean±std 到 `paper_eval_summary_*.csv`。  
- 若暂不改 run_paper_eval，也可先单独跑各脚本，再手动画表对比。

---

## 七、实现顺序建议

1. **passfail_data.py**：实现 (u,i) 划分、原始特征（单向量 + 序列）、与 main_passfail 一致的 (u,i)→label 映射。  
2. **extract_embeddings.py**：预训练表示提取（单向量 + 序列），严格按 train/val/test 边划分，输出与 passfail_data 的 (u,i) 对齐。  
3. **train_logistic.py**：`pure` 与 `contratgt` 两种 mode，共用上述数据接口。  
4. **train_lstm.py**：同上，序列版特征 + LSTM 模型 + 课程级评估。  
5. **train_mlp.py**（可选）：纯 MLP 基线。  
6. 视需要更新 **run_paper_eval.py** 与 **README**，说明新脚本及对比表含义。

按此方案实现后，即可得到「ContraTGT + Logistic / LSTM」与「纯 Logistic / 纯 LSTM」（及可选纯 MLP）的公平对比，且与现有 main_passfail（ContraTGT + MLP 头）在划分与评估口径上一致。
