# code/script 性能瓶颈与优化方案

## 一、数据规模对比

| 数据 | 边数 (ml_*.csv 行数-1) | 节点数 (content 行数) |
|------|------------------------|------------------------|
| **data_abc_0.01** | **31,256** | **2,526** |
| **ml_wiki.csv** | **107,071** | (约 8k+ 节点) |

**结论**：data_abc_0.01 的边数约为 ml_wiki 的 **1/3.4**，节点数也更少。若用 0.01 数据仍然很慢，主要瓶颈在 **脚本内部的热点**，而不是数据规模。

---

## 二、耗时最大的地方（按优先级）

### 1. `get_unique_node_sequence`（sampling.py）——最可能的主瓶颈

- **位置**：`sampling.py` 约 103–164 行。
- **行为**：对当前 batch 里每条边，根据 `from_node` 和当前边在时间上的位置，从 **整张图的边表** 里取「该节点在此时间之前的边」，拼成时序序列。
- **为何极慢**：
  - 对每条 batch 边（例如 800 条），内层有：
    - `idx_list[from_node].index(idx)`：在列表上线性查找，复杂度 O(该节点度数)。
    - `for j, ed in enumerate(f_edge['idx'][0:last_event])` 或 `f_edge['idx'][last_event - row:last_event]`：**按「边下标」遍历整张图的边**。`last_event` 最大可到训练边数（data_abc_0.01 约 2.5 万），所以单次调用复杂度约 **O(batch_size × 训练边数)**。
  - `main.py` 里每个 batch 会调 4 次（batch / to / fake 等），`pretrain.py` 里每个 batch 调 6+ 次。
- **量级**：data_abc_0.01 下，单 epoch 仅这一项就可能达到 **batch 数 × 4 × (800 × 2.5万)** 级别的内层循环，是整条 pipeline 里最重的部分。

### 2. pretrain.py 里每 batch 多次 `torch.load(MIDDLE_PATH)`

- **位置**：`pretrain.py` 约 92 行，在「top_k」阶段的内层循环里。
- **行为**：每个 batch 里，`for se in range(6)` 每次都会执行 `mid_model.load_state_dict(torch.load(MIDDLE_PATH))`，即 **每个 batch 从磁盘读同一个 pth 至少 6 次**；后面「model」阶段还有类似逻辑。
- **为何慢**：重复磁盘 I/O + 反序列化，且 MIDDLE_PATH 不变，完全可只加载一次、在内存里复用。

### 3. `get_neighbor_list`（sampling.py）——纯 Python 逐条处理

- **位置**：`sampling.py` 约 62–89 行。
- **行为**：对 batch 里每个 (node, timestamp) 调用 `find_before` 做二分查找，再在 Python 里填 `ngh_node/ngh_ts/ngh_idx/ngh_mask`。
- **为何慢**：整段是「for i, edg in enumerate(zip(node, timestamp))」的 Python 循环，没有向量化；且每个 batch 在 main/pretrain 里会被调用很多次（spatial 多处、fake 等），调用次数 × batch_size 的循环次数就很大。

### 4. 每个 batch 里用 Python 双循环填特征

- **位置**：`main.py` / `pretrain.py` 里多处，例如：
  - `for idx, i in enumerate(batch_ngh_node): for idj, j in enumerate(i): con_seq_fea[idx, idj, :] = features[j]`。
- **行为**：按 (batch, ctx_sample) 用 Python 两层循环，从 `features` 里按节点索引拷贝到 `con_seq_fea` 等。
- **为何慢**：纯 Python 循环 + 逐元素赋值，没有用 NumPy/PyTorch 的整块索引（如 `features[batch_ngh_node]`），在 batch 大、ctx_sample 大时会被放大。

### 5. Dataset() 里为 node_time 的 O(边数) Python 循环

- **位置**：`utils.py` 约 142–149 行。
- **行为**：`for i, edg in enumerate(edges)`，对每条边更新 `node_time[st]`、`node_time[en]`。
- **为何慢**：只跑一次，但 3 万多条边纯 Python 循环，且列表下标访问多，相比后面「每个 batch 都跑」的采样，占比小一些，但仍可优化。

## 三、修改方案建议

### 方案 1：优化 `get_unique_node_sequence`（优先）

- 用「边索引/时间」做预处理，使「某节点在某时间之前的边」能 **按节点+时间 O(1) 或 O(log n) 取出一段**，而不是每次 `enumerate(f_edge['idx'][0:last_event])` 扫全表。
- 例如：对每个节点预先按时间排好边索引，再对 batch 里每个 (node, ts) 只做一次二分或查表，得到「前 last_event 条边」的区间，用数组切片或高级索引一次性取出，避免对 2.5 万条边做 800 次大循环。
- 同时把 `idx_list[from_node].index(idx)` 换成二分或 dict 查找，避免 O(degree) 线性扫描。

### 方案 2：去掉 pretrain 里重复的 `torch.load(MIDDLE_PATH)`

- 在每个 batch 开始前（或每个 epoch 开始前）只 `load_state_dict(torch.load(MIDDLE_PATH))` 一次，将 `mid_model` 保持在内存中，内层 `for se in range(6)` 只做前向/反向，不再每次从磁盘加载。
- 若需要「固定住某时刻的 mid_model」，可在循环外 clone 或复制一份 state_dict，而不是反复读盘。

### 方案 3：向量化或加速 `get_neighbor_list`

- 用 NumPy 高级索引或 PyTorch 张量操作，对整批 (node, timestamp) 一次性做「在 node_l/ts_l/offset_l 上的二分/切片」，得到整批的邻居列表，再统一填 `ngh_node/ngh_ts/ngh_idx/ngh_mask`，避免 per-sample 的 Python 循环。
- 若保留循环，至少用 Numba 对 `find_before` 或整段邻居采样做 JIT，减少 Python 解释开销。

### 方案 4：用整块索引替代「双重 for 填特征」

- 将 `batch_ngh_node` 等做成形状为 (batch_size, ctx_sample) 的整型数组/张量，用 `features[batch_ngh_node]`（或等价写法）一次性得到 (batch_size, ctx_sample, indim)，避免两层 Python for + 逐元素赋值。

### 方案 5：Dataset() 里 node_time 的向量化

- 用 `edges` 的列向量和 `timestamp`，按 (st, en) 和 (ts) 用 NumPy 的 `minimum.at` 或类似方式，在「每条边只更新一次」的语义下，一次性写出 `node_time`，避免 3 万次 Python 循环。

### 方案 6：训练超参与规模上的「减负」

- 在 0.01 数据上调试时：适当减小 `ctx_sample`、`tmp_sample`、`n_epoch`，或增大 `bs`，可成比例减少 `get_neighbor_list` / `get_unique_node_sequence` 的调用次数和 batch 数，便于先验证「优化 1、2」是否已明显缩短时间。

---

## 四、总结

| 优先级 | 热点 | 建议 |
|--------|------|------|
| 高 | `get_unique_node_sequence` | 预处理 + 二分/查表 + 整块索引，避免「每条 batch 边扫全图」 |
| 高 | pretrain 重复 `torch.load` | 每 batch/epoch 只 load 一次，mid_model 放内存 |
| 中 | `get_neighbor_list` | 向量化或 Numba JIT |
| 中 | 双循环填特征 | 用 `features[...]` 整块索引 |
| 低 | Dataset node_time | 向量化一次写入 |

**优先做 1 和 2**：1 直接决定「每个 batch 是否还在扫整张图」，2 能立刻去掉大量重复磁盘 I/O。
