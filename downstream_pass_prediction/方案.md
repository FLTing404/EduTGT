# 下游课程通过预测（`is_pass`）方案 — 仅 D1（原始图数据）

> **范围说明**：本文档只描述 **D1**——使用现有预处理得到的 **原始学生–站点动态图**（`ml_*.csv` + `*.content`），不在下游阶段引入「第二套增广边表」或「预训练式在线增广数据管线」。**预训练权重**（`outputs/pretrain/<data_name>.pth`）仅作为编码器初始化选项，与「另一份数据」无关。

---

## 1. 目标与 D1 数据定义

### 1.1 任务

对 **整模块** 图 `data_AAA` … `data_GGG`（与 `data/processed/data_<MODULE>/` 对应，每个目录内可含多个 `code_presentation` 的边与节点），根据学生在图上的 **VLE 交互**，预测该生 **在该模块上下文下、与图覆盖范围一致** 的注册结果是否通过（二分类标签 `is_pass`）。标签与划分均落在下游自有目录，**不改动** 既有 `pretrain` / `main` 使用的 `data/processed`。

### 1.2 下游专用 `data/` 目录（与前置实验隔离）

**原则**：所有「打 `is_pass` 之后」的下游产物只写在 **`EduTGT/downstream_pass_prediction/data/`** 下；**绝不** 在 `data/processed/data_*` 里增删改文件，避免影响你已跑完的预训练 / 链路实验。

**按模块一份子目录**（本方案覆盖 `AAA`–`GGG`）：

```text
EduTGT/downstream_pass_prediction/data/
├── data_AAA/
├── data_BBB/
│   └── ...
└── data_GGG/
```

**每个 `data_<MODULE>/` 建议固定包含**：

| 文件或子目录 | 说明 |
|--------------|------|
| `labels_pass.parquet`（或 `.csv`） | 对齐图后的样本表：至少含 `id_student`、`code_module`、`code_presentation`（若整模块多实例则保留）、`is_pass`，以及可选 `graph_student_idx` |
| `splits/train_students.txt`、`val_*.txt`、`test_*.txt` | 按学生划分结果 |
| `manifest.json`（推荐） | 记录本模块对应的 **只读** 图源：`data/processed/data_<MODULE>/` 下 `ml_*.csv`、`*.content`、`node_map.csv` 的相对路径、预处理版本或哈希（便于复现） |
| `graph_mirror/`（可选） | 若你希望下游目录 **完全自包含**：由脚本 **复制**（非移动）`ml_*.csv`、`*.content`、`node_map.csv` 等到此子目录；**源目录 `data/processed` 仍保持只读、与复制前一致** |

训练脚本应 **优先读 `manifest` 指向的图路径**；若存在 `graph_mirror/` 且配置为使用镜像，则读镜像，便于打包或换机复现。

**训练日志与权重**：仍可写在 `outputs/downstream_pass/`（见第 8 节），与 `outputs/pretrain/`、`outputs/models/` 分离。

### 1.3 D1 图数据读入（唯一图管线，只读）

| 来源 | 路径约定 | 作用 |
|------|-----------|------|
| 动态边 | `data/processed/data_<MODULE>/ml_*.csv`（或由 `manifest` / `graph_mirror` 解析） | 学生→站点、带时间戳 `ts`；与 `utils.Dataset`、`pretrain.py` 一致 |
| 节点特征 | 同目录下 `*.content` | 一行一节点；与边中节点 id 经 `Dataset` 重映射后对齐 |
| 节点名映射 | `node_map.csv`（若预处理已生成） | `student::<id_student>` → 与图一致的节点标识，用于对齐标签 |

**D1 的含义**：图数据 **仍以现有预处理结果为权威来源**；下游只在 `downstream_pass_prediction/data/` 中累积 **标签、划分、清单**，不在原 `processed` 目录上「再加工一份 ml」。**Dataset** 中邻居采样、batch 构造与 `main.py` 类似的 **常规** `ctx_sample` / `tmp_sample`。

### 1.4 与预训练的关系（概念拆分）

- **数据**：下游始终读 **上述 D1 文件**；预训练同样在该 `data_name` 上完成时，与下游 **共享同一图域**。  
- **权重**：下游编码器可选 **随机初始化**，或 **加载** `paths.pretrain_ckpt_path(data_name)` 对应的 `.pth`。这是 **参数初始化**，不改变 `ml` / `content` 文件内容。

## 2. 标签构建（Raw OULAD → `is_pass`）

### 2.1 输入表

- 使用 **`data/raw/OULAD`**（或你配置的 raw 根目录）中的 **`studentInfo.csv`**（OULAD 中 **`final_result`** 在该表；若你本地只有 `studentRegistration.csv` 且无成绩列，需自行 join 或换源）。
- 必需逻辑字段至少包括：`id_student`、`code_module`、`code_presentation`、`final_result`。

### 2.2 与当前图对齐（`data_AAA`–`data_GGG` 整模块）

1. 下游选用的 **`data_name`** 与目录一致，例如 **`data_AAA`** … **`data_GGG`**（与 `data/processed/data_AAA` 等一一对应）。  
2. **整模块** 时，图中可能包含 **多个 `code_presentation`**：以 **`stats.json` 的 `code_presentations_merged`**（与预处理一致）在 **`studentInfo`** 中过滤行，保证标签覆盖与 **该 `data_<MODULE>` 图** 一致。  
3. 每一行注册记录对应 **一个样本**：键为 **`(id_student, code_module, code_presentation)`**，值为 **`is_pass`**；若同一学生在同一模块下有多条 presentation 注册，则 **多条样本**（与多条标签行一致），划分仍按 **学生** 时需约定是否「同一学生在模块内合并为一条」（推荐：**按 presentation 一条标签、划分仍按 `id_student`** 时，该学生所有 presentation 落在同一 split，见第 3 节）。

### 2.3 `is_pass` 映射规则（固定后全文统一）

| `final_result`（示例） | `is_pass` |
|------------------------|-----------|
| `Pass`、`Distinction` | `1` |
| `Fail`、`Withdrawn` | `0` |

其他取值（若有）：在实验说明中单列一条规则（例如丢弃或单独类别），**不得**在 train/test 之间不一致。

### 2.4 与图节点对齐

1. 由 `node_map.csv` 找到形如 `student::<id_student>` 的行，得到图中学生节点在 **重映射后** 的下标（或与 `Dataset` 输出一致的 id）。  
2. **丢弃** 在注册表有记录、但在图中 **无学生节点** 或 **无任何边** 的样本（若采用，需在报告中统计比例）。  
3. 输出 **`downstream_pass_prediction/data/data_<MODULE>/labels_pass.parquet`（或 `.csv`）**：建议列 `id_student`、`graph_student_idx`（或等价）、`code_module`、`code_presentation`、`is_pass`，供划分与 Dataset 使用；**不写入** `data/processed/`。

## 3. 数据集划分：按学生（`id_student`）

### 3.1 划分单位

- **粒度**：**`id_student`**。  
- **原则**：同一 `id_student` **只出现在一个** 集合（train / val / test 之一），避免同一学生的习惯信息从 train 泄漏到 test。

### 3.2 推荐比例与分层

- 比例示例：**70% / 15% / 15%**（train / val / test）。  
- 使用 **分层抽样**（按 `is_pass` stratify），使各集 **正负比例** 接近全量分布。  
- **随机种子**：固定 `seed`；若报告稳健性，可 **多 seed** 重复划分，报告指标均值与方差。

### 3.3 产出物

- 写入 **`downstream_pass_prediction/data/data_<MODULE>/splits/`** 下：  
  **`train_students.txt` / `val_students.txt` / `test_students.txt`**（每行一个 `id_student`），或等价 JSON/CSV。  
- 若同一学生在模块内对应 **多条 `(module, presentation)` 标签行**，划分文件仍只含 **`id_student`**，训练时取该生所有落在 train split 的样本参与训练（或按你实现的 sample 粒度在文档中固定一种）。  
- 下游训练 **只读 train 的标签**；val 用于 **选学习率、early stopping、超参**；**test 仅在最终一次评估使用**。

### 3.4 为何不采用「按边 (u,i) 划分」

学生–站点 **多条边** 属于同一时间展开的行为轨迹；若随机拆边到 train/test，会 **割裂同一学生的序列** 并引入 **信息泄漏**。本方案 **固定为学生级划分**。

## 4. 输入行为与时间截断 \(t^\*\)

### 4.1 两种叙事（二选一写进报告）

| 模式 | 行为输入 | 适用表述 |
|------|-----------|-----------|
| **早期预警** | 仅使用 **`ts < t*`** 的边（及由这些边诱导的邻居采样）预测 **课程结束后的 `is_pass`** | 「在时刻 \(t^\*\) 能看到的范围内预测最终结果」 |
| **期末复盘** | 使用 **全学期** 边（不截断 \(t^\*\)） | 与「未来」预测区分，避免表述矛盾 |

**主推荐**：早期预警；\(t^\*\) 可取相对日（与 OULAD 导出 `ts` 语义一致）或课长比例，需在配置中 **显式记录**。

### 4.2 截断下的图与采样

1. 对每个样本学生，从 `ml_*.csv` 取出其所有边，**过滤** `ts < t*`。  
2. **构图 / 邻接**：仅用过滤后的边构建 **用于前向的** `adj_list` 或等价结构（实现可与全图预计算后 mask 等价，但语义须是「截断后可见」）。  
3. 若截断后 **边数为 0**（冷启动）：在方案中 **固定一种策略**——例如 **丢弃该样本** 或 **使用可学习/零向量占位**；两种策略 **不可混用** 于同一组对比实验。

### 4.3 与预训练的时间一致性（说明义务）

若预训练在 **全时间** `ml` 上完成，而下游采用 **\(t^\*\) 截断**，则编码器在预训练阶段见过 **\(t^\*\) 之后** 的交互分布。这不等于标签泄露，但属于 **任务设定与预训练信息不对齐**；报告或论文中应 **写明**；若需更严对照，见 **第 6.3 节**。

## 5. 模型、损失与训练细节（D1）

### 5.1 结构

1. **编码器**：`SpatialTemporal`（与 `model.py` 中用于 `pretrain.py` / `main.py` 的配置对齐：`in_dim`、`out_dim`、`n_heads`、`N`、`dropout` 等与当前项目一致或可配置）。  
2. **分类头**：将学生表示 \(h_u \in \mathbb{R}^{d}\) 映射为 logit，**Sigmoid + BCE** 或直接用 **`BCEWithLogitsLoss`**。  
3. **学生表示 \(h_u\)**：以锚点边为 batch 中的「当前交互」，用与 `main.py` **源端** 一致的 **时空邻居采样**（`ctx_sample`、`tmp_sample`），再经 **`SpatialTemporal.getEmbed`** 得到向量，接 **线性分类头**（实现见 `st_encode.py`）。

### 5.2 损失与类别不平衡

- 主损失：**二分类交叉熵**（logit 版）。  
- 若正负极不均衡：可使用 **`pos_weight`**、重采样 batch、focal loss 等；**同一对比实验**（随机 init vs 预训练）须用 **同一策略**。

### 5.3 优化与早停

- 优化器：如 **Adam**，权重衰减与 `main.py` 量级可比（如 `1e-5`）。  
- 学习率：可在 **val** 上网格或手动设定；**两种初始化** 可各用 val 选一组 lr，但 **不得** 用 test 选。  
- Early stopping：以 **val 上 AUC 或 AUPRC** 等主指标为准， patience 固定。

### 5.4 主实验组（仅 D1）

| 编号 | 编码器初始化 | 说明 |
|------|----------------|------|
| **E1** | **随机初始化** | 对照组 |
| **E2** | **加载** `outputs/pretrain/<data_name>.pth` | 检验 EduTGT 预训练是否提升通过预测 |

**固定一致**：D1 数据、学生划分、\(t^\*\)（若启用）、网络结构、训练预算与选参协议。

## 6. 随机初始化 vs 预训练权重：泄露、公平性与可宣称结论

### 6.1 泄露辨析

| 类型 | 说明 | 常规结论 |
|------|------|-----------|
| **标签泄露** | test 的 `is_pass` 进入训练或预训练 | 预训练通常不用成绩表；下游只用 train 标签 → **一般不发生标签泄露** |
| **直推式预训练** | 全图 `ml` 含 test 学生的无标签交互 | **非标签泄露**；若宣称严格「预训练未见 test 学生交互」则需 **归纳式预训练**（6.3） |
| **时间不对齐** | 全时间预训练 + \(t^\*\) 前预测 | 须在文中 **声明**；更严做法见 6.3 |

### 6.2 公平对比条件

- 同一 **D1**、同一 **按学生划分**、同一 **\(t^\*\)**（若用截断）、同一 **编码器结构** 与 **训练协议**；超参仅用 **val** 调整。  

在此条件下，E1 vs E2 支持结论：

> 在已声明的 **全图无监督预训练 + 按学生有监督微调** 设定下，预训练初始化是否优于随机初始化。

**不应**未经 6.3 类实验就将结果等同于 **严格归纳泛化**。

### 6.3 可选加强实验（非必须）

1. **归纳式预训练**：仅在 train 学生子图上预训练，再加载权重做下游。  
2. **时间对齐**：预训练与下游均只用 \(t^\*\) 前的边。  

可与主设定 **并列报告**。

## 9. 端到端流程（实现 checklist）

对 **`data_AAA` … `data_GGG`** 逐个模块执行（或批处理脚本循环）：

1. **准备图数据（已有流水线，只读）**  
   确认 `data/processed/data_<MODULE>/` 下已有 `ml_*.csv`、`*.content`、`node_map.csv`。**不要** 在本流程中修改该目录。

2. **预训练（若跑 E2，沿用你已有实验）**  
   `python pretrain.py --data_dir data/processed/data_<MODULE> ...` → `outputs/pretrain/data_<MODULE>.pth`。下游 **只读** 该权重，不写回 `data/processed`。

3. **构建标签表（写入下游目录）**  
   `build_pass_labels.py`：读 `data/raw/OULAD/studentInfo.csv`（`final_result`），按 `stats.json` 中 module 与 `code_presentations_merged` 过滤，映射 `is_pass`，用 `node_map.csv` 对齐学生节点 → **`downstream_pass_prediction/data/data_<MODULE>/labels_pass.csv`** + **`manifest.json`**。

4. **按学生划分（写入下游目录）**  
   `build_student_splits.py`：读上一步标签表 → 分层划分 → 写出 **`downstream_pass_prediction/data/data_<MODULE>/splits/*.txt`**。

5. **SpatialTemporal 通过预测 E1 / E2（当前实现）**  
   `run_train_st_pass.py`：`--init scratch` 为 **E1**，`--init pretrain` 为 **E2**（加载 **`outputs/pretrain/<data_name>.pth`**，只读）。按 `manifest` 读全图做邻居/时间采样（与 `main.py` 源端一致），锚点边定义见 **`README.md`**；`t_star_relative_day` 在 `configs/default.yaml` 或命令行。

6. **测试集评估**  
   仅 **test_students**；指标追加 **`downstream_pass_prediction/outputs/data_<MODULE>/runs_st.jsonl`**。

## 10. 风险与注意事项

1. **目录隔离**：任何下游脚本 **不得** 向 `data/processed/` 写入；标签与 split **仅** 在 `downstream_pass_prediction/data/`。  
2. **模块一致**：本方案针对 **`data_AAA`–`data_GGG`** 整模块目录；若混用单实例 `data_AAA_2013J`，过滤规则与标签行须与 **该目录图范围** 一致。  
3. **类别语义**：Withdrawn 是否算「未通过」已与 2.3 固定；高比例时需讨论业务含义。  
4. **冷启动样本**：与 4.2 策略一致。  
5. **表述**：E1/E2 结论边界见 **第 6 节**。
